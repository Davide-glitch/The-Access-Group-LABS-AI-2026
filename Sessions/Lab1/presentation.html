Definitions

What is "AI"?

Artificial Intelligence is the field of building systems that perform tasks normally associated with human cognition — perception, reasoning, language, decision-making.

Symbolic AI

Hand-coded rules, logic, search. Great for narrow, well-defined problems. Brittle outside them.

Machine Learning

Systems that learn patterns from data instead of being explicitly programmed.

Deep Learning

ML using large neural networks. The engine behind almost all of today's breakthroughs.

The core technology

What is a Large Language Model?

An LLM is a neural network trained to predict the next token (roughly: word piece) given everything that came before.

That single objective — over trillions of tokens of text — produces a model that can summarise, translate, code, reason step-by-step, and follow instructions.

It's not a database, a search engine, or a person. It's a learned distribution over plausible continuations of text.

What they're good at

Capabilities

Language

Summarisation, translation, rewriting, extraction, classification.

Code

Generation, refactoring, debugging, explaining, test writing.

Reasoning

Multi-step problems, planning, analysis — improving fast with "thinking" models.

Knowledge work

Drafting, research synthesis, structured data extraction from messy inputs.

Multimodal

Images, audio, video, documents — increasingly native to the model.

Tool use

Calling APIs, running code, querying databases. The bridge to action.

Where they fail

Sharp edges

  • Hallucination. Confident output that isn't grounded in fact. Mitigated, not solved, by retrieval and tools.
  • Stale knowledge. Training data has a cutoff. The model doesn't know what's happened since.
  • No real memory. A bare LLM is stateless — it only "remembers" what's in the current context window.
  • Brittleness to phrasing. Small changes in prompts can produce large changes in output.
  • Cost & latency. Big models are expensive per token; agentic loops multiply that cost.

The interface

Prompting, briefly

The prompt is the program. Treat it like one:

  • Be specific about role, task, and output format
  • Give examples (few-shot) when behaviour matters
  • Provide the data it needs — don't rely on memory
  • For hard problems, ask it to think step by step
  • Iterate: prompts are debugged, not written

A decent template

You are a {role}. Goal: {what success looks like}. Constraints: {format, length, tone}. Context: {relevant data} Task: {the actual ask}

Grounding

Retrieval-Augmented Generation (RAG)

Don't ask the model what it remembers — give it the documents and ask it to answer from them.

QuestionUser input
→
RetrieveSearch vector DB / index
→
AugmentStuff context into prompt
→
GenerateLLM answers from sources

Reduces hallucination, keeps knowledge fresh, and gives you citations. It's the single most common LLM application pattern in production.

The shift

What is Agentic AI?

A model that doesn't just answer — it acts. Given a goal, it plans, takes steps, uses tools, observes results, and adapts until the goal is met.

Chatbot

One turn in, one turn out. Human drives every step.

Agent

Goal in, result out. Model decides the steps, calls tools, reflects, retries.

Building blocks

Anatomy of an agent

Model

The reasoning core. Decides what to do next.

Tools

Functions it can call: search, code execution, APIs, file I/O.

Memory

Short-term (context) and long-term (vector store, files, DB).

Planner

Decomposes a goal into steps — sometimes implicit, sometimes a separate component.

Loop

Observe → think → act → observe. The engine that turns a model into an agent.

Guardrails

Permissions, validation, human-in-the-loop checkpoints, budgets.

Take seriously

Risks & responsibilities

  • Hallucination at scale. An agent acting on a wrong belief does damage faster than a chatbot does.
  • Prompt injection. Untrusted text in tool outputs can hijack the agent's instructions.
  • Privacy & data leakage. What you put in the prompt may flow to logs, training data, or third parties.
  • Cost runaway. Loops + big models = surprising bills. Add budgets and step limits.
  • Accountability. When an agent acts, someone is responsible. Design for traceability and human review.

Practical advice

If you're building with this

  • Start narrow. Pick one task, do it well, then expand.
  • Ground the model — RAG, tools, structured outputs.
  • Write evals before you write prompts. You can't improve what you can't measure.
  • Treat prompts as code: version, review, test.
  • Prefer the smallest model that works. Cost compounds in agent loops.
  • Log everything. Traces beat guesses.
  • Keep humans in the loop where the blast radius is real.
  • Assume the model will be wrong — design for graceful failure.

What's next

Where this is heading

  • Longer-horizon agents. From minutes of autonomy to hours, then days, on real tasks.
  • Native multimodality. Voice, vision, video as first-class inputs and outputs.
  • Smaller, cheaper, local. Capable models running on your laptop, your phone, your edge device.
  • Better tool ecosystems. Standard protocols (e.g. MCP) so agents plug into the world reliably.
  • The interesting bottleneck stops being the model and becomes the surrounding system: evals, memory, oversight, integration.
