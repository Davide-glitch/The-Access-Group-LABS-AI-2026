Microsoft Agent Framework 1.0

The framework we'll use today

MAF is an open-source SDK and runtime for building AI agents in .NET and Python. GA since April 3, 2026 — stable APIs, long-term support.

The unified successor of two earlier Microsoft projects:

Semantic Kernel Enterprise foundations — session state, middleware, telemetry, type safety
AutoGen Simple agent abstractions and multi-agent orchestration patterns
MAF 1.0 → Both merged into one framework. Same team, one foundation, production-ready.

What it gives us in this lab:

Tool registration

Annotate a C# method → MAF generates the JSON schema and routes calls automatically.

Model-agnostic

Same code works with OpenAI, Azure OpenAI, Claude, Gemini, Ollama and more.

Session & memory

Built-in multi-turn state so the agent remembers previous steps in the conversation.

MCP + A2A (Lab 3+)

Plug into external tool servers and coordinate with other agents across runtimes.

Motivation

The problem with a bare LLM

An LLM knows how to predict tokens. That's it.

It cannot:

  • Execute code
  • Access an external API
  • Read a file from disk
  • Check the current time or an exchange rate
  • Write to databases

Tool calling is the bridge between knowing and doing.

Without tool calling

User: What's the EUR/USD rate right now? Model: Based on my training data from [cutoff date], the rate was around 1.08. // ← could be completely wrong
Theory

How tool calling works

The model does not execute the code — it returns a structured JSON. You run the function and send the result back.

Theory

Anatomy of a function schema

[Description("Get the current weather for a city")] public static WeatherResult GetWeather( [Description("City name, e.g. Bucharest")] string city, [Description("Unit: 'celsius' or 'fahrenheit'")] string unit = "celsius") { // mock — replace with real API call return new WeatherResult(city, 22, unit, "Sunny"); }

The model sees the description, not the implementation.

  • The function description tells it when to call it
  • Parameter descriptions tell it what to send
  • C# types → JSON schema automatically
Description attribute Type inference Auto-schema

Describe behaviour, not implementation. The model is a documentation reader.

Code

How to add a tool to an agent

// 1. Define the function with Description [Description("Get the current weather for a city")] public static WeatherResult GetWeather( [Description("City name, e.g. Bucharest")] string city, [Description("Unit: 'celsius' or 'fahrenheit'")] string unit = "celsius") { return new WeatherResult(city, 22, unit, "Sunny"); } // 2. Register it with the agent agent.AddFunction(GetWeather); // 3. Run — the model decides when to call it await agent.RunAsync("What's the weather like in Paris?");

The model reads [Description] and decides on its own:

  • When to call the tool
  • What arguments to send
  • How to interpret the result

You write a normal C# function. The framework generates the schema, routes the call, and injects the result into context.

Hands-on · Exercise 03 bonus — 10 min

Tool approval workflow

Some tools are dangerous to run without confirmation:

  • Database writes
  • Sending emails / notifications
  • Financial transactions
  • Any irreversible action

MAF has FunctionApprovalRequestContent built-in: the agent proposes the call and waits for your confirmation before executing.

// agent proposes a tool call var result = await agent.RunAsync(msg); if (result is FunctionApprovalRequestContent req) { Console.WriteLine($"Approve: {req.FunctionName}?"); var ok = Console.ReadLine() == "y"; await agent.ResumeAsync( new FunctionApprovalResponseContent( req, approved: ok)); }
Pitfalls

What can go wrong

  • Vague description → wrong tool called. "Do something with currency" isn't enough. Be specific: what does the function do, when does it make sense to call it.
  • Parameters without Description. The model will guess what to send — and will guess wrong. Every parameter needs context.
  • Tool that throws an uncaught exception. The agent stalls. Catch exceptions and return a structured error message — the model will adapt.
  • Too many tools. Giving the model 30 functions increases the chance it picks the wrong one. Group or filter contextually.
  • Uncontrolled loops. An agent can call a tool, misinterpret the result, and loop. Add a maxTurns limit.
