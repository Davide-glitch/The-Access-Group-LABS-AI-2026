From List<Chunk> to a real vector database

Start from the Lab 3 solution and migrate it step by step to IVectorStore — first backed by an in-memory store, then swapped to Qdrant for persistence.

01

Add NuGet packages

Open Lab4.csproj and add two new package references inside the existing <ItemGroup>. Keep the existing Microsoft.Agents.AI and OpenAI references — you're adding to them, not replacing them.

<ItemGroup> <PackageReference Include="Microsoft.Agents.AI" Version="1.3.0" /> <PackageReference Include="Microsoft.Agents.AI.OpenAI" Version="1.3.0" /> <PackageReference Include="OpenAI" Version="2.10.0" /> <PackageReference Include="Microsoft.Extensions.VectorData.Abstractions" Version="10.1.0" /> <PackageReference Include="Microsoft.SemanticKernel.Connectors.InMemory" Version="1.74.0-preview" /> </ItemGroup>
Why these two? Microsoft.Extensions.VectorData.Abstractions gives you the IVectorStore interface and the record attributes ([VectorStoreKey], etc.). Microsoft.SemanticKernel.Connectors.InMemory provides the in-memory implementation — same behaviour as Lab 3's list, but going through the standard interface.

Also add SKEXP0001;SKEXP0020 to the <NoWarn> element, since the Semantic Kernel connectors are still marked experimental:

<NoWarn>$(NoWarn);MEAI001;OPENAI001;SKEXP0001;SKEXP0020</NoWarn>
Version compatibility is strict These three packages must be used together at exactly these versions. Microsoft.Agents.AI 1.3.0 requires OpenAI ≥ 2.10.0. Microsoft.SemanticKernel.Connectors.InMemory 1.74.0-preview was compiled against VectorData.Abstractions 10.1.0 — using a newer version of the abstractions package will cause a runtime TypeLoadException. Don't let NuGet silently upgrade VectorData.Abstractions beyond 10.1.0.

03

Remodel the Chunk type

Lab 3 used a simple positional record. Vector store connectors need a class with property attributes so they know which field is the key, which fields are payload, and which field is the vector.

Lab 3 — before
record Chunk( float[] Vector, string Text, string Source );
Lab 4 — after
class Chunk { [VectorStoreKey] public Guid Id { get; set; } = Guid.NewGuid(); [VectorStoreData] public string Text { get; set; } = ""; [VectorStoreData] public string Source { get; set; } = ""; [VectorStoreData(IsIndexed = true)] public string Category { get; set; } = ""; [VectorStoreVector(Dimensions: 1536, DistanceFunction = DistanceFunction.CosineSimilarity)] public ReadOnlyMemory<float> Vector { get; set; } }

Three things worth noting:

  • Key: Every record needs a unique key. Guid.NewGuid() generates one automatically on creation.
  • IsIndexed = true: Only fields marked with this can be used in filter expressions. We'll use Category for filtering in step 9.
  • Vector type: Changed from float[] to ReadOnlyMemory<float> — this is what the connector expects.
04

Create the vector store and collection

In the config section at the top of Program.cs, replace the List<Chunk> with an IVectorStore and get a typed collection from it.

Lab 3 — before
var store = new List<Chunk>(); var kb = new KnowledgeBase( store, embeddingClient);
Lab 4 — after
IVectorStore vectorStore = new InMemoryVectorStore(); var collection = vectorStore .GetCollection<Guid, Chunk>( "company-docs"); await collection .EnsureCollectionExistsAsync();
Why declare IVectorStore instead of InMemoryVectorStore? When we swap to Qdrant in step 12, only this one line changes. The rest of the code talks to IVectorStore and doesn't care what's behind it.
Don't forget EnsureCollectionExistsAsync Without this call, the first UpsertAsync will fail. It's a no-op if the collection already exists, so it's safe to call every startup. Note: this method was renamed from CreateCollectionIfNotExistsAsync in v1.74.0-preview — don't use the old name.
05

Add the InferCategory helper

Add this static helper function at the bottom of Program.cs, alongside the existing Chunker class. It maps each document filename to a category tag that we'll store with every chunk.

static string InferCategory(string filename) => filename switch { var f when f.StartsWith("leave") || f.StartsWith("benefit") || f.StartsWith("onboarding") => "HR", var f when f.StartsWith("it-") => "IT", var f when f.StartsWith("expense") => "Finance", var f when f.StartsWith("product") => "Product", _ => "General", };

We'll call this in the next step during ingestion to tag each chunk before storing it.

06

Update the ingestion loop

Replace the inner loop in the ingestion section. Instead of calling kb.EmbedAsync() and adding to a list, we now embed directly and upsert into the collection.

Lab 3 — before
foreach (var file in Directory.GetFiles(docsPath, "*.md")) { var text = await File .ReadAllTextAsync(file); var chunks = Chunker.Split( text, 1500, 200); var count = 0; foreach (var chunk in chunks) { var vector = await kb .EmbedAsync(chunk); store.Add(new Chunk( vector, chunk, Path.GetFileName(file))); count++; } // ... }
Lab 4 — after
foreach (var file in Directory.GetFiles(docsPath, "*.md")) { var text = await File .ReadAllTextAsync(file); var category = InferCategory( Path.GetFileName(file)); var chunks = Chunker.Split( text, 1500, 200); var count = 0; foreach (var chunk in chunks) { var result = await embeddingClient .GenerateEmbeddingAsync(chunk, embeddingOptions); var vector = new ReadOnlyMemory<float>( result.Value.ToFloats().ToArray()); await collection.UpsertAsync(new Chunk { Text = chunk, Source = Path.GetFileName(file), Category = category, Vector = vector, }); count++; } // ... }

Also update the Console.WriteLine at the end of the outer loop to print the category alongside the chunk count:

Console.WriteLine($" {Path.GetFileName(file),30} → {count} chunk(s) [{category}]");
07

Update the KnowledgeBase constructor

The KnowledgeBase class no longer needs the List<Chunk> — it now works through the collection. Update its primary constructor parameter.

Lab 3 — before
class KnowledgeBase( List<Chunk> store, EmbeddingClient embeddingClient)
Lab 4 — after
class KnowledgeBase( VectorStoreCollection<Guid, Chunk> collection, OpenAI.Embeddings.EmbeddingClient embeddingClient, OpenAI.Embeddings.EmbeddingGenerationOptions embeddingOptions)

You'll also need to declare embeddingOptions near the top of the config section and pass it through. Add this right after you create the embeddingClient:

var embeddingClient = openAIClient.GetEmbeddingClient(embeddingModelId); var embeddingOptions = new OpenAI.Embeddings.EmbeddingGenerationOptions { Dimensions = 1536 };

Then update the KnowledgeBase instantiation in the agent setup section:

var kb = new KnowledgeBase(collection, embeddingClient, embeddingOptions);
Why set Dimensions explicitly? Pinning Dimensions = 1536 makes the code resilient to model swaps — if you override GITHUB_EMBED_MODEL to text-embedding-3-large (which defaults to 3072 dims), the output is still clipped to 1536 so it matches the vector store schema. It also serves as documentation: the reader can see the dimension without needing to look up the model.
08

Replace the cosine search with SearchAsync

This is the biggest change. The manual cosine similarity loop inside SearchAsync is replaced by a call to the collection's built-in SearchAsync method.

Lab 3 — before
var queryVector = await EmbedAsync(query); var results = store .Select(c => ( Chunk: c, Score: CosineSimilarity( queryVector, c.Vector))) .OrderByDescending(x => x.Score) .Take(topK) .Where(x => x.Score > 0.4f) .ToList(); if (results.Count == 0) return "No relevant info found."; return string.Join("\n\n---\n\n", results.Select(r => $"[Source: {r.Chunk.Source}]\n" + r.Chunk.Text));
Lab 4 — after
var result = await embeddingClient .GenerateEmbeddingAsync(query, embeddingOptions); var queryVector = new ReadOnlyMemory<float>( result.Value.ToFloats().ToArray()); var options = new VectorSearchOptions<Chunk>(); var results = new List<string>(); await foreach (var hit in collection.SearchAsync(queryVector, topK, options)) { results.Add( $"[Source: {hit.Record.Source}" + $" | Score: {hit.Score:P0}]\n" + hit.Record.Text); } if (results.Count == 0) return "No relevant info found."; return string.Join("\n\n---\n\n", results);
Why await foreach instead of ToList? SearchAsync returns IAsyncEnumerable<VectorSearchResult<Chunk>> — results stream back one at a time, which matters when the collection is large or remote. You must use await foreach to iterate it. You can't call .ToList() directly on an IAsyncEnumerable.
top is the second positional argument, not a property In VectorData.Abstractions 10.1.0 the Top property was removed from VectorSearchOptions. The result count is now the second argument to SearchAsync: collection.SearchAsync(vector, topK, options). If you put Top = topK inside the options initialiser the code won't compile.

Also remove the EmbedAsync helper method from KnowledgeBase — embedding is now done inline in both ingestion and search using embeddingClient directly.

09

Add a category filter parameter

Now that chunks have a Category field, we can expose it as an optional filter. The agent will use it to narrow searches when the topic is obvious.

Update the SearchAsync signature to accept an optional category, and pass it as a filter to VectorSearchOptions:

[Description("Search the company knowledge base...")] public async Task<string> SearchAsync( [Description("The user's question, rephrased as a search query")] string query, [Description("Optional category filter: HR, IT, Finance, Product. Leave empty to search all.")] string? category = null, [Description("Number of results to return. Default is 3.")] int topK = 3) { // ... embedding code from step 8 ... var options = new VectorSearchOptions<Chunk> { Filter = !string.IsNullOrEmpty(category) ? r => r.Category == category : null, }; // pass topK as second positional arg (not a property of options) await foreach (var hit in collection.SearchAsync(queryVector, topK, options)) // ... build results list ... }
Why is the filter a lambda? The Filter property takes a LINQ expression — r => r.Category == category — which the connector translates into whatever the backing store supports (an in-memory predicate, a Qdrant filter payload, etc.). Only fields marked IsIndexed = true can be used here.
Use IsNullOrEmpty, not != null When the LLM decides no category filter is needed it passes an empty string "", not null. If you guard the filter with category != null, an empty string slips through and your search returns zero results (no chunk has Category == ""). Always use !string.IsNullOrEmpty(category).

Update the agent's system prompt to mention the filter:

instructions: "You are a helpful company assistant for Acme Software Ltd. " + "For any question about internal topics, always call search_knowledge_base first. " + "You may pass a category filter (HR, IT, Finance, Product) when the topic is clear. " + "Cite the source document when you use retrieved information."
10

Delete CosineSimilarity

The CosineSimilarity static method inside KnowledgeBase is no longer needed — the vector store handles similarity calculation internally. Delete it.

// ← delete this entire method static float CosineSimilarity(float[] a, float[] b) { float dot = 0, magA = 0, magB = 0; for (int i = 0; i < a.Length; i++) { dot += a[i] * b[i]; magA += a[i] * a[i]; magB += b[i] * b[i]; } return dot / (MathF.Sqrt(magA) * MathF.Sqrt(magB)); }
Checkpoint The project should compile cleanly at this point. If you see any CS errors, check that all references to store (the old list) have been replaced with collection, and that any remaining calls to EmbedAsync on the knowledge base have been replaced with direct embeddingClient.GenerateEmbeddingAsync() calls.

GitHub Models daily embedding quota The free tier of GitHub Models enforces a per-model daily quota on embedding API calls. If ingestion hangs indefinitely at the first document, you've likely hit the text-embedding-3-small daily limit — the SDK silently respects the Retry-After header which can be 22+ hours. To work around it, set GITHUB_EMBED_MODEL=openai/text-embedding-3-large before running — it has a separate daily quota. The code's Dimensions = 1536 option clips the output so the vector schema stays identical.

What's the same, what's different Behaviour is identical to Lab 3. The code is structurally different — but from the outside you can't tell. That's the point: the abstraction layer gave us a clean swap without changing observable behaviour.
12

Swap to Qdrant

Now for the payoff. Start Qdrant in Docker, then change one line of code.

1. Start Qdrant:

docker run -d \ -p 6333:6333 \ -v qdrant_storage:/qdrant/storage \ qdrant/qdrant

The -v flag mounts a named Docker volume so the data survives container restarts. Browse to localhost:6333/dashboard to confirm Qdrant is running.

2. Add the Qdrant NuGet package to Lab4.csproj:

<PackageReference Include="Microsoft.SemanticKernel.Connectors.Qdrant" Version="1.74.0-preview" />

3. Add the using at the top of Program.cs:

using Microsoft.SemanticKernel.Connectors.Qdrant; using Qdrant.Client;

4. Comment out InMemory, uncomment Qdrant — this is the only change to the logic:

// IVectorStore vectorStore = new InMemoryVectorStore(); var qdrantClient = new QdrantClient("localhost"); IVectorStore vectorStore = new QdrantVectorStore(qdrantClient);
Qdrant must be running before the program starts The connection is made on the first API call. If Docker isn't running you'll get a connection refused error. Check docker ps to confirm the container is up.
13

Verify persistence — add the warm-start skip

With Qdrant running, the collection survives process restarts. We can check for it at startup and skip ingestion when the data is already there.

Wrap the entire ingestion block in a CollectionExistsAsync check:

var collectionExists = await collection.CollectionExistsAsync(); if (!collectionExists) { var docsPath = Path.Combine(AppContext.BaseDirectory, "Docs"); Console.WriteLine($"Ingesting documents from {docsPath}..."); foreach (var file in Directory.GetFiles(docsPath, "*.md")) { // ... your ingestion loop ... } Console.WriteLine($"\nReady — chunks indexed.\n"); } else { Console.WriteLine("Collection already exists — skipping ingestion.\n"); }

Now run the program twice:

First run — ingestion happens, all 6 documents are embedded and stored in Qdrant. Note how long it takes.

Ingesting documents from .../Docs... benefits-handbook.md → 2 chunk(s) [HR] expense-policy.md → 2 chunk(s) [Finance] it-helpdesk-faq.md → 3 chunk(s) [IT] ... Company assistant ready.

Second run — ingestion is skipped entirely. The program is ready almost instantly.

Collection already exists — skipping ingestion. Company assistant ready.
Explore the Qdrant dashboard Open localhost:6333/dashboard. Click on the company-docs collection. You'll see all your chunks stored as points — each one with its 1536-dimensional vector and payload fields (Text, Source, Category). This is what you'd previously only have had in RAM.
Resetting the index If you change a document or want to force a full re-index, delete the collection and restart:
await collection.DeleteCollectionAsync();
The next run will recreate it from scratch.
