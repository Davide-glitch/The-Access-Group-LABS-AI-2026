Build QuizMaster: fetch, build, run

Your first real React app, in three movements. First you fetch the quizzes already on your API and render them. Then you build a screen that lets you create a quiz in the browser — add questions, add answer options — holding it all in React state. Finally you run the quiz: step through the questions one at a time. Fetching teaches data; building and running teach state.

Part B · Fetch data from the API
02

Tour the starter

The starter is bare on purpose. Here's what's there now — and what you'll create as you work through the guide.

src/ what's already here types/quiz.ts ✓ ApiQuiz + Quiz/Question/Answer (given) index.css ✓ all the styling (given) App.tsx ✓ placeholder — you fill it in (step 08) main.tsx ✓ React entry point you'll create: api/quizzes.ts fetchQuizzes() (step 04) components/QuizCard.tsx presentational card (step 03) components/ExistingQuizzes.tsx fetch + render the list (step 05) components/QuizBuilder.tsx build a quiz in state (step 06) components/QuizRunner.tsx run a quiz (step 07)

Open src/types/quiz.ts — the one piece of the data model you don't have to type out. There are two families of type, and the comment in the file explains why:

src/types/quiz.ts
// What the API returns from GET /quizzes — read only. export type ApiQuiz = { id: string; title: string; description?: string; ownerId: string; }; // What you build in the browser — lives only in React state. export type Answer = { id: string; text: string; }; export type Question = { id: string; text: string; answers: Answer[]; }; export type Quiz = { id: string; title: string; questions: Question[]; };
Two types, because there are two kinds of quiz The quizzes on the server are flat records you only read. The quizzes you build are nested (a quiz has questions, a question has answers) and you mutate them constantly. Notice there's no isCorrect — this app doesn't grade, it just records which option you picked.
03

Create QuizCard — props in, JSX out

Make a components/ folder and create src/components/QuizCard.tsx. It's the simplest kind of component — pure presentation — and both the API list and your own quizzes render through it, so it's the right place to start. Type it out and read it as you go:

src/components/QuizCard.tsx

Don't forget the import at the very top — action is a React node:

import type { ReactNode } from 'react';
type QuizCardProps = { title: string; subtitle?: string; action?: ReactNode; // an optional button the parent supplies }; function QuizCard({ title, subtitle, action }: QuizCardProps) { return ( <div className="quiz-card"> <div className="quiz-card-text"> <h3>{title}</h3> {subtitle && <p>{subtitle}</p>} </div> {action && <div className="quiz-card-action">{action}</div>} </div> ); }
Props, not state — and an action slot QuizCard owns nothing; it only reads what it's handed. The action prop is a ReactNode — the parent decides whether to pass a "Run" button or nothing at all. The card just gives it a place to sit. That's how you keep a presentational component reusable.
04

Fetch the quizzes

Create an api/ folder and src/api/quizzes.ts. This is the one function in the app that talks to the backend:

src/api/quizzes.ts
import type { ApiQuiz } from '../types/quiz'; const API_BASE = 'http://localhost:5023'; export async function fetchQuizzes(): Promise<ApiQuiz[]> { const res = await fetch(`${API_BASE}/quizzes`); if (!res.ok) throw new Error(`HTTP ${res.status}`); return res.json(); }

It isn't called yet — that's the next step, from inside a useEffect. For now, just confirm the dev server doesn't complain.

If you see a CORS error next step It means the API in step 00 isn't running, or its UseCors() isn't wired correctly. A CORS error always means the browser blocked the response — the request reached the server fine.
05

Wire up ExistingQuizzes — state, effect, honest states

Create src/components/ExistingQuizzes.tsx. Three pieces of state — the data, plus whether we're loading and whether we failed — an effect that fetches once, and a render that handles every case.

src/components/ExistingQuizzes.tsx
import { useEffect, useState } from 'react'; import QuizCard from './QuizCard'; import { fetchQuizzes } from '../api/quizzes'; import type { ApiQuiz } from '../types/quiz'; function ExistingQuizzes() { const [quizzes, setQuizzes] = useState<ApiQuiz[]>([]); const [loading, setLoading] = useState(true); const [error, setError] = useState<string | null>(null); useEffect(() => { fetchQuizzes() .then(setQuizzes) .catch((err: Error) => setError(err.message)) .finally(() => setLoading(false)); }, []); // empty array — run once, on mount if (loading) return <p className="status-message">Loading quizzes from the API...</p>; if (error) return <p className="status-message error">Couldn't load quizzes: {error}</p>; if (quizzes.length === 0) return <p className="status-message">No quizzes on the server yet.</p>; return ( <div className="quiz-list"> {quizzes.map((quiz) => ( <QuizCard key={quiz.id} title={quiz.title} subtitle={quiz.description} /> ))} </div> ); }

Nothing renders it yet, so let's render it from App to see it work. Open src/App.tsx and, just for now, drop <ExistingQuizzes /> into the <main> (you'll replace this with the real App in step 08):

src/App.tsx (temporary)
import ExistingQuizzes from './components/ExistingQuizzes'; function App() { return ( <div className="app"> <header className="app-header"><h1>QuizMaster</h1></header> <main><ExistingQuizzes /></main> </div> ); } export default App;

With the API running, you'll see the three seeded quizzes appear.

Verify both paths Open the Network tab and reload — exactly one request to /quizzes, not a loop. Then stop the API (Ctrl+C) and reload — you should see the error message, not a blank space.
The two classic mistakes 1. Drop the [] and the effect runs after every render — and since it calls a setter, that's an infinite fetch loop. 2. Only clear loading in .then() and a failed request spins forever; .finally() runs on both paths.
Part C · Build & run your own quiz — state management
06

Build the QuizBuilder — nested state, immutably

This is the heart of the lab. Create src/components/QuizBuilder.tsx. It takes two callbacks from its parent — onCreate to hand back a finished quiz, and onCancel — and holds the quiz being built in local state. Start with the skeleton:

src/components/QuizBuilder.tsx
import { useState } from 'react'; import type { Question, Quiz } from '../types/quiz'; type QuizBuilderProps = { onCreate: (quiz: Quiz) => void; onCancel: () => void; }; function QuizBuilder({ onCreate, onCancel }: QuizBuilderProps) { /* state + handlers + save + a form, all below */ } export default QuizBuilder;

Your job: hold a list of questions, each with its own list of answers, and update them without mutating the existing arrays. Here are the state and the handlers — a controlled title input, plus immutable add/update functions for questions and answers:

const [title, setTitle] = useState(''); const [questions, setQuestions] = useState<Question[]>([]); // Each handler builds NEW arrays/objects — never mutates the old ones — // so React sees a new reference and re-renders. function addQuestion() { setQuestions((qs) => [...qs, { id: crypto.randomUUID(), text: '', answers: [] }]); } function updateQuestionText(qid: string, text: string) { setQuestions((qs) => qs.map((q) => (q.id === qid ? { ...q, text } : q))); } function addAnswer(qid: string) { setQuestions((qs) => qs.map((q) => q.id === qid ? { ...q, answers: [...q.answers, { id: crypto.randomUUID(), text: '' }] } : q)); } function updateAnswerText(qid: string, aid: string, text: string) { setQuestions((qs) => qs.map((q) => q.id === qid ? { ...q, answers: q.answers.map((a) => (a.id === aid ? { ...a, text } : a)) } : q)); }

Then render one editor block per question — a text input bound to updateQuestionText, its answers each bound to updateAnswerText, an "+ Add answer" button, and an "+ Add question" button below the list. Finally, "Create quiz" and "Cancel" buttons. save() ties the form back to the parent:

function save() { if (title.trim() === '' || questions.length === 0) return; // (show a warning) onCreate({ id: crypto.randomUUID(), title: title.trim(), questions }); }
Why immutable updates, really React decides whether to re-render by comparing references. If you push() into the existing questions array and call setQuestions(questions), it's the same array reference — React skips the render and your UI freezes. Spreading ([...qs, ...], { ...q, text }) makes a new reference every time. This is the single most common state bug in React.
The updater form setQuestions((qs) => ...) Passing a function to the setter gives you the latest state, which matters when several updates happen close together. Prefer it whenever your new state is derived from the old.
Verify Nothing renders QuizBuilder yet — that's wired in step 08. To eyeball it now, you can temporarily render <QuizBuilder onCreate={console.log} onCancel={() => {}} /> from App: type a title, add questions and answers, hit "Create quiz", and watch the finished quiz object print in the console. Then put App back.
07

Run the quiz — one question at a time

Create src/components/QuizRunner.tsx. It receives the quiz to run and a callback to exit ({ quiz, onExit }, typed with quiz: Quiz and onExit: () => void). Track three things: which question you're on, the option picked per question, and whether you've finished.

src/components/QuizRunner.tsx
const [current, setCurrent] = useState(0); const [picks, setPicks] = useState<Record<string, string>>({}); const [finished, setFinished] = useState(false); const question = quiz.questions[current]; const isLast = current === quiz.questions.length - 1; function pick(answerId: string) { setPicks((prev) => ({ ...prev, [question.id]: answerId })); // remember the pick }

While not finished, render the current question, its answers as clickable options (highlight the one in picks[question.id]), and navigation: a "Previous" button (disabled at index 0), and either "Next" (setCurrent(c => c + 1)) or, on the last question, "Finish" (setFinished(true)). When finished, show a summary listing each question and the option the user chose, plus a "Back to home" button that calls onExit().

No grading — on purpose There's no "correct" answer in this model, so "run" means navigate and record, not score. That keeps the focus on the state mechanics: an index you move, a map you accumulate, a boolean that flips the whole view. Scoring would just be one more derived value on top — a natural homework extension.
Verify (after step 08) The runner needs App to hand it a quiz, so the real test comes once you wire App in the next step: build a quiz, click "Run", step forward and back — your earlier picks should still be highlighted when you return to a question (that's the picks map doing its job) — then finish and confirm the summary matches what you chose.
Part D · Tie it together
08

Wire it all together in App

Now replace your temporary App with the real one. App owns two things: the quizzes you build, and which screen (view) is showing. It renders the builder, the runner, or the home screen accordingly — passing data down as props and receiving changes back through callbacks.

src/App.tsx
import { useState } from 'react'; import ExistingQuizzes from './components/ExistingQuizzes'; import QuizBuilder from './components/QuizBuilder'; import QuizRunner from './components/QuizRunner'; import QuizCard from './components/QuizCard'; import type { Quiz } from './types/quiz'; type View = { name: 'home' } | { name: 'build' } | { name: 'run'; quizId: string }; function App() { const [quizzes, setQuizzes] = useState<Quiz[]>([]); const [view, setView] = useState<View>({ name: 'home' }); function addQuiz(quiz: Quiz) { setQuizzes((qs) => [...qs, quiz]); setView({ name: 'home' }); } const running = view.name === 'run' ? quizzes.find((q) => q.id === view.quizId) : undefined; return ( <div className="app"> <header className="app-header"> <h1 onClick={() => setView({ name: 'home' })}>QuizMaster</h1> </header> <main> {view.name === 'build' && ( <QuizBuilder onCreate={addQuiz} onCancel={() => setView({ name: 'home' })} /> )} {view.name === 'run' && running && ( <QuizRunner quiz={running} onExit={() => setView({ name: 'home' })} /> )} {view.name === 'home' && ( <> <button className="btn-primary" onClick={() => setView({ name: 'build' })}>+ New quiz</button> {quizzes.map((q) => ( <QuizCard key={q.id} title={q.title} subtitle={`${q.questions.length} questions`} action={<button onClick={() => setView({ name: 'run', quizId: q.id })}>Run</button>} /> ))} <ExistingQuizzes /> </> )} </main> </div> ); } export default App;
Why quizzes lives in App, not QuizBuilder Several components need to agree on it: the builder adds to it, the home list and the runner read from it. The closest component that contains all of them is App, so the state lives there and flows down as props. That's "lifting state up." Notice the per-quiz editing state (the half-built questions) stays inside QuizBuilder — nobody else needs it, so it doesn't get lifted.
Verify end to end Click "+ New quiz", build one with a couple of questions and answers, "Create quiz" — it appears under your quizzes. Click "Run", step through it, finish, land back home. And with the API up, the server's quizzes still list below. That's the whole app.
09

Homework — take it further

You have an app that reads from your API and lets you build and run quizzes entirely in state. Extend it, and note your choices in a short README.md next to your code.

Pick at least two:

  • Mark a correct answer. Add an isCorrect flag per answer in the builder (a radio per question), then score the run and show "X / N correct" on the summary. This is the natural next layer on top of picks.
  • Delete a quiz. Add a "Delete" action to each home card. You'll lift a removeQuiz(id) handler out of App and pass it down — the mirror of onCreate.
  • Validation. Block "Create quiz" until every question has text and at least two answers, with inline messages instead of a single warning.
  • Persist to localStorage. Save quizzes on change and load it on mount with a useEffect, so your quizzes survive a refresh — the same effect pattern as fetching, but against the browser instead of the network.
  • Extract a hook. Move the fetch state out of ExistingQuizzes into a useQuizzes() hook. Your first reusable hook.
The rules to carry forward 1. Update state immutably — new references, every time. 2. State belongs to the closest component that needs it; don't lift further than that. 3. An effect's dependency array isn't decoration — get it wrong and you get an infinite loop or stale data.
Stretch goal Make "Create quiz" actually POST to /quizzes. It will get a 401 in the browser today — that's correct, not a bug. Write down what you'd need (a captured bearer token, an Authorization header) to make it work; you'll build exactly that in the session that introduces sign-in.
